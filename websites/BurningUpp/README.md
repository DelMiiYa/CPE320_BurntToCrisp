# BurningUpp — เว็บปัจจุบันสำหรับทำต่อ

โฟลเดอร์นี้คือซอร์สเว็บที่ทีมสร้างและแก้ต่อ ไม่ใช่เว็บสำรองหรือเวอร์ชันใหม่
มี Frontend HTML/CSS/JavaScript, Backend FastAPI/SQLite และชุดทดสอบปัจจุบัน
`project-spec.json` เป็นข้อกำหนดสำหรับให้หัวหน้าทีมทำงานต่อ ไม่ได้แปลว่าทุกข้อผ่านการตรวจรับแล้ว

## เปิดผ่าน Office เพื่อให้ Agent ทำต่อ

จากราก repository หลังติดตั้งตาม README หลัก:

```sh
python -m se_team.office --import-website websites/BurningUpp
```

เปิด http://127.0.0.1:8787 เลือก BurningUpp แล้วกด “เว็บของคุณ → เปิดเว็บหลัก”
การนำเข้าลงทะเบียนไฟล์เดิม ไม่คัดลอกเว็บ ไม่สร้างเว็บใหม่ และไม่เรียกโมเดล
การเปิดครั้งต่อไปด้วยคำสั่งเดิมจะใช้โปรเจกต์และประวัติบนเครื่องนั้นต่อ
เมื่อส่งคำสั่งให้ Agent ต้องล็อกอิน Antigravity หรือ Codex ด้วยบัญชีของตัวเอง

## เปิดเฉพาะเว็บโดยไม่ใช้ Agent

```sh
python -m se_team.office.preview --source websites/BurningUpp --port 8788
```

เปิด http://127.0.0.1:8788 แล้วสมัครองค์กร/บัญชีใหม่ผ่านหน้าจอ
ไม่ต้องมีบัญชี Antigravity เพื่อเปิดหรือแก้เว็บด้วยตัวเอง
ข้อมูลใหม่เก็บใน `data/` ของเว็บ ไม่ถูกส่งเข้า Git

## รันทดสอบ

จากราก repository:

```sh
python scripts/check.py --website
```

ใช้ข้อมูลชั่วคราวแยกจากบัญชีและข้อมูลในเว็บที่เปิดอยู่
ไม่ต้องเพิ่ม `backend/test_backend.py` เข้า pytest อีกครั้ง เพราะมี wrapper ใน `tests/` เรียกอยู่แล้ว

## งานที่ยังต้องทำต่อ

- งานล่าสุดที่ยังทำไม่เสร็จ: เปลี่ยนตัวเลือกเดือนปฏิทินเป็น GUI และปรับ dropdown/UI
  งานนั้นหมดเวลาก่อนรับไฟล์ใหม่ จึงยังไม่ถือว่าทำตามข้อกำหนดนี้แล้ว
- ชุดทดสอบอัตโนมัติเดิมผ่าน 125 รายการ ณ การส่งต่องาน แต่ยังต้องตรวจ browser journeys,
  มือถือ/เดสก์ท็อป การเข้าถึง และกรณี 401/เครือข่ายจริงเพิ่มเติม
- ผลตรวจล่าสุดยังเป็น `needs_attention` ไม่ได้อนุมัติส่งมอบครบทุก acceptance criterion
- สูตรประเมิน burnout และระบบชำระเงินจริงยังไม่ถูกกำหนด/เปิดใช้

## สิ่งที่ไม่ติดมาจากเครื่องผู้พัฒนา

ไม่มีฐานข้อมูล บัญชีผู้ใช้/session แชต Office เครดิต หรือข้อมูลล็อกอิน CLI
เพื่อนจะเริ่มด้วยข้อมูลว่างและใช้บัญชีของตัวเอง ซอร์สเว็บและข้อกำหนดอยู่ครบสำหรับพัฒนาต่อ
รายละเอียด Backend และกติกาข้อมูลอยู่ใน `backend/README.md`
