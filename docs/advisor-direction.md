# แนวทางจากการคุยกับอาจารย์ และการนำมาใช้

แหล่งข้อมูล: คลิป “Srinakharinwirot University - Ongkharak Campus 13.m4a”
ยาวประมาณ 13 นาที 54 วินาที สรุปจากข้อความที่ถอดเสียงบนเครื่อง
บางช่วงเสียงไม่ชัด จึงใช้เฉพาะประเด็นที่จับความได้ต่อเนื่อง เวลาด้านล่างเป็นเวลาโดยประมาณ
เอกสารนี้เป็นสรุปความ ไม่ใช่คำพูดถอดตรงของอาจารย์

## สิ่งที่ได้จากบทสนทนา

| ช่วงเวลา | ประเด็น | ผลต่อข้อกำหนด |
| --- | --- | --- |

แนวคิด mood tracking, การประเมิน burnout และบทบาท manager/member ปรากฏใน
การอธิบายของผู้พัฒนาในคลิปด้วย จึงไม่ถือว่าทุกรายละเอียดเป็นข้อสั่งการใหม่จากอาจารย์
คลิปไม่ได้ยืนยันสูตรประเมิน เกณฑ์คะแนน ราคา หรือเทคโนโลยีที่ต้องใช้เป็นข้อกำหนดตายตัว

## สิ่งที่ผู้ใช้ขอเพิ่มในแชตนี้

- คุยกับหัวหน้า Agent ตัวเดียว แล้วหัวหน้าแบ่งงานให้ Agent เฉพาะทาง
- เปลี่ยนจาก SWU API ไปใช้ Codex

สองเรื่องนี้เป็นความต้องการของผู้ใช้ ไม่ได้อ้างว่าเป็นคำแนะนำจากอาจารย์

## การตัดสินใจในการพัฒนาครั้งนี้

- ใช้ Supervisor + Frontend + Backend + QA โดยยังใช้ CrewAI Flow เป็นตัวส่งงาน
- หัวหน้าออก spec/contract/คำสั่งเฉพาะบทบาทและเลือก build_batches;
  ระบบส่งงานตามแผนจริง ไม่ใช่เพียงเปลี่ยนชื่อ role ใน YAML
- ใช้ Codex CLI ผ่าน `codex exec` และล็อกอินที่มีอยู่ แทนการตั้ง SWU endpoint
  ตัวเชื่อมรันในเครื่อง ส่วนโมเดล OpenAI ยังต้องใช้อินเทอร์เน็ต
- ใช้ subscription แบบจำลอง/เปิดใช้งานด้วยผู้ดูแลเป็นขอบเขต MVP ที่หัวหน้าต้อง
  ระบุสมมติฐานให้ชัด การชำระเงินจริงและราคาเป็นเรื่องที่ยังต้องกำหนด
- กำหนดให้มีการติดตามผลและแยกสิทธิ์ข้อมูลข้ามองค์กรเป็น acceptance criteria
  นี่คือการแปลงเป้าหมายจากคลิปเป็นงานที่ทดสอบได้ ไม่ใช่รายละเอียดที่อาจารย์สั่งตรงทุกข้อ
- ไม่ใช้เกณฑ์คะแนน PA ที่กลับทิศแล้วร่วมกับ threshold ของคะแนนดิบโดยอัตโนมัติ
  ให้หัวหน้าระบุ scoring convention และกติกาที่ยืนยันแล้วก่อนสร้าง tests

ส่วนที่แก้ในครั้งนี้คือระบบ Agent ที่จะสร้างแอปตาม brief เมื่อรัน
ยังไม่ได้สร้างหรือทดสอบ BurningUpp ที่พร้อมใช้งานจริง และไม่ได้เชื่อมระบบชำระเงิน
